# IFFI Consultant: website

**www.ifficonsultant.com**, a study-in-China site for IFFI Consultant. Next.js 16 (App Router) + React 19 +
TypeScript + Tailwind CSS v4. Every page is statically generated (120 routes), with a China programme map
and three free tools. `MASTER_PROMPT.md` is the original specification.

## What is in it

| Area | Where |
|---|---|
| Routes, metadata (titles, descriptions, canonicals, keywords, Open Graph), sitemap, robots | `src/app/**/page.tsx`, `src/app/sitemap.ts`, `src/app/robots.ts`, `src/lib/metadata.ts` |
| Page bodies (Server Components unless they need state) | `src/views/*` |
| Home with the China programme map (SVG first, three.js on desktop interaction or "View in 3D") | `src/views/Home.tsx`, `src/components/map/*` (`load3d.ts` decides when 3D loads) |
| University & Programme Finder: filters, URL sync, shortlist, PDF print sheet, compare | `src/views/Finder.tsx`, `src/components/programmes/*`, `src/lib/filters.ts` |
| 72 programme pages and 21 province pages | `src/views/ProgrammeDetail.tsx`, `src/views/ProvincePage.tsx` |
| Study Cost Calculator, Scholarship Eligibility Checker | `src/views/CostCalculator.tsx`, `src/views/EligibilityChecker.tsx`, `src/lib/cost.ts`, `src/lib/eligibility.ts` |
| Blog: 9 articles written around the keyword research | `src/content/blog.ts` |
| JSON-LD (organisation, breadcrumbs, FAQ, articles, services) | `src/lib/seo.ts`, `src/components/ui/Seo.tsx` |
| Staff programme editor | `/staff/programmes`, `src/app/api/staff/programs/*` |
| Student portal: online application, documents with samples, signing, QR fee | `src/app/portal/**`, `src/lib/portal/*`, `src/components/portal/apply/*` |
| Staff portal: applications, document and payment checks, notes, activity log, settings | `src/app/staff/**`, `src/lib/staff/*`, `src/components/staff/*` |

Data comes only from `src/data/*.json` (generated by `../data-pipeline`, see `DATA_DICTIONARY.md`). University
names are never shown.

### Data modules: keep heavy and light apart

| Import | Contains | Use from |
|---|---|---|
| `@/data/content` | site copy, contacts, SEO routes, WhatsApp messages, counts | server components, page.tsx |
| `@/data/core` | the client slice of the copy (brand, contacts, navigation, WhatsApp messages, disclaimers) and counts | client components |
| `@/data/places` | provinces | anywhere |
| `@/data/config` | tools config (currencies, cost tables) | anywhere |
| `@/data/catalog` | the full programme list (~220 KB) | server components, page.tsx, tool pages only |
| `@/data/geo` | map geometry (114 KB) | the lazy map components only |
| `@/data/keywords` | ranked SEO keywords | page.tsx metadata only (server-only) |

Client components import `@/data/core`, not `@/data/content`: the full copy (FAQ, blog seeds, services, SEO) would
otherwise ship to every visitor. Importing `@/data/catalog` into a component that renders on every page (header, layout, providers) puts the
whole programme list into every visitor's download. `src/lib/programs.ts` is light; helpers that need the full
list live in `src/lib/catalog.ts`.

## Run it locally

```powershell
npm install
npm run dev          # http://localhost:3000 (shows draft content with amber "Draft" badges)
npm run build        # production build, prints the route table
npm start            # serve the build at http://localhost:3000
npm run typecheck
npm run seo:audit    # after a build: title / H1 / description / canonical / keyword checks per route
```

Contacts and legal details the client has not confirmed are `null` in `site.json` and simply do not render.

## Deploy to Vercel

1. Push this repository to GitHub.
2. Vercel → Add New → Project → import the repository. If the repo also holds the research files, set
   **Root Directory = `iffi-consultant`**. Framework preset: Next.js (detected).
3. Settings → Domains: add `ifficonsultant.com` and `www.ifficonsultant.com`; let the apex redirect to `www`
   (the canonical URLs use `www`). Point the domain's DNS at Vercel as it instructs.
4. Optional environment variables:

```
NEXT_PUBLIC_GA4_ID=G-XXXXXXX          # Google Analytics 4; the cookie banner appears only when this is set
NEXT_PUBLIC_FORM_ENDPOINT=https://…   # contact form POST target (JSON). Without it the form opens WhatsApp pre-filled.
```

Do **not** set `ADMIN_PASSWORD` / `ADMIN_SECRET` on Vercel: the admin is a local tool (Vercel's disk is read-only).
Old PHP URLs (`about.php`, `blog-post.php?slug=…`) redirect permanently via `next.config.mjs`, which also sets the
security headers.

After the first deploy: Google Search Console + Bing Webmaster Tools → add the domain → submit
`https://www.ifficonsultant.com/sitemap.xml`, and check PageSpeed Insights on the live URL.

## Student application (portal)

"Apply online" on a programme page starts an application at `/portal/applications/<id>`, eight steps:

| Step | Where | What happens |
|---|---|---|
| 1-5 Form | `/[section]` (`personal`, `contact`, `education`, `study`, `family`) | IFFI's official application form as data (`src/lib/portal/form.ts`). Prefilled from the quiz and Google account, saves itself as the student types, checked in the browser and again on the server. |
| 6 Documents | `/documents` | The list comes from IFFI's charges list plus the brochure (`requiredDocuments()` in `src/lib/portal/documents.ts`). Every document has a drawn sample with numbered points (`DocSample.tsx`). Files go straight from the browser to private Supabase Storage through one-time signed URLs (big phone photos are shrunk first). |
| 7 Review and sign | `/review` | All answers, the declaration from the official form, signature = passport name typed. Changing an answer later removes the signature. |
| 8 Fee | `/fee` | Refund policy (versioned, acceptance recorded) → QR code and account details → transaction ID + screenshot. Status becomes "Payment being checked". After the JW202, the same page takes the service charge (`?for=service`). |

The two forms students fill in by hand are in `private/forms/` (served to signed-in users by `/portal/forms/[file]`):
the blank Word application form and the Foreigner Physical Examination Form. `/portal/print/<id>` shows the
application form laid out like the original and **filled in from the student's answers**, ready to print and sign.

Staff see everything on `/staff/applications/<id>`: progress by step, every answer, each file (preview, download,
accept or ask for a new one with a note), payments (confirm or "not found"), the adviser in charge, the fees for this
application, staff-only notes or messages to the student, and an activity log of every action by anyone. The
dashboard shows files waiting to be checked (oldest first) and the applications assigned to whoever is signed in. Admins set the payment QR
code, account details and default fees in `/staff/settings` (no redeploy needed; fees stay empty until IFFI decides).

Setup: run `supabase/migrations/0004_application_wizard.sql` in the Supabase SQL Editor (after 0001-0003). It adds
the tables, the private `application-files` bucket (50 MB per file, the free plan's maximum) and the policies.

Emails (`src/lib/notify/*`): students get an email when IFFI changes the status, asks for a new file, checks a payment
or sends a message; the IFFI inbox gets one for each new application, payment to check and "it is fixed". They go out
over Gmail SMTP: turn on 2-Step Verification for ifficonsultant@gmail.com, create an App Password (Google Account →
Security → App passwords) and set `SMTP_USER` and `SMTP_PASS` (locally in `.env.local`, and in the host's environment
variables). Without them nothing is sent and everything else works. Set `APP_URL` to the live address while the domain
is not connected, so links in emails work.
Decide in `submissionBlockers()` (`src/lib/portal/documents.ts`) which missing documents block signing and paying.

## Staff programme editor

Staff and administrators can manage degree programmes directly in the Staff Portal under `/staff/programmes`.
In development (`npm run dev`), edits update `src/data/programs.json` directly; commit the file and Vercel redeploys.
Re-running `data-pipeline/parse_programs.py` regenerates that file from the brochures and overwrites edits.

## Speed notes

- First-load JS is ~160–175 KB gzipped on content pages; about 135 KB of that is the Next.js / React runtime.
- Measured with Lighthouse 12 against `next start` on a Windows laptop (local headless Chrome adds ~0.8 s before the first
  paint, so real numbers on Vercel's CDN should be a little better): desktop 92–99 on every route checked; mobile about
  90–92 on content pages, mid/high 80s on programme pages and the cost calculator, about 80 on the home page, ~73 on the finder.
- What keeps it fast: Server Components for static sections, the programme list kept out of shared bundles,
  drawers and maps loaded on demand, no animation library, intent-based link prefetching, self-hosted fonts
  (only the upright display font is preloaded), and no full-page SVG filters.

## Images

`public/og-image.png` (link previews) is generated by `scripts/og-image.mjs` from the brand, domain and counts in
`src/data`; re-run it when those change. Logo crests are 512 px PNG masters resized by `next/image`.
